# Gallery Cover Mode

## Область аудита

Gallery Cover Mode — локальная маскировка приложения под офлайн-галерею. Пользовательские фотографии и настройки Gallery должны оставаться только на текущем устройстве и не экспортироваться, не попадать в backup и не переноситься на другое устройство.

## Хранилище и приватность

- Изображения выбираются только через системный Android Photo Picker; широкие разрешения на медиатеку не запрашиваются.
- Выбранное изображение декодируется и заново кодируется перед локальным сохранением. Исходные EXIF/XMP/IPTC/MakerNote/GPS и идентифицирующие метаданные в sanitized-копию не переносятся.
- В зашифрованном индексе могут сохраняться размеры, название color space, время съёмки и ограниченный набор неидентифицирующих параметров съёмки.
- Изображения, thumbnails, индекс и альбомы шифруются AES-256-GCM с неэкспортируемым ключом Android Keystore и отдельным AAD для каждого назначения.
- Файлы Gallery находятся в `noBackupFilesDir`. Общие правила backup/D2D исключают все данные приложения, а `DeviceTransferGuard` очищает скопированные приватные данные, если device-local Keystore marker не подтверждается.

## Устойчивость к сбоям

Метаданные Gallery фиксируются через `AtomicFile`. Редактирование изображения использует copy-on-write: новая зашифрованная версия изображения и thumbnail записываются до переключения индекса на них, а прежние файлы удаляются только после успешного commit индекса. При обычной ошибке импорта созданные этой операцией файлы удаляются. После успешной расшифровки и загрузки закоммиченного индекса удаляются незарегистрированные encrypted image/thumbnail-файлы.

## Скрытый вход

- Во время настройки выбирается секретное локальное изображение.
- Код состоит ровно из трёх разных зон из пяти: четыре угла и центр.
- Порядок важен, поэтому допустимо 60 последовательностей.
- Последовательность вводится дважды при настройке.
- В plaintext она не сохраняется. `GalleryAccessManager` хранит ID секретного изображения и HMAC-SHA256 verifier с ключом Android Keystore.
- Сравнение verifier выполняется constant-time способом.
- Текущая попытка сбрасывается по timeout, повтору зоны, смене изображения, тапу вне секретной зоны, заметному drag/swipe, multi-touch/zoom, навигации viewer, запуску recovery и действиям нижней панели.
- Уже запущенная асинхронная проверка становится недействительной, если sequence был сброшен или состояние viewer изменилось.

### Ограничение безопасности

Текущая схема из трёх разных зон имеет только 60 комбинаций и не использует постоянный rate-limit/lockout. HMAC защищает сохранённый verifier, но не увеличивает энтропию пользовательского жеста. Это ограничение текущего Gallery v1 и такую последовательность нельзя считать высокоэнтропийным фактором аутентификации. Расширение пространства жестов или политика ограничения попыток должны приниматься как отдельное продуктовое/безопасностное решение, поскольку они меняют существующую семантику входа.

## Аварийное восстановление

Gallery использует общий recovery flow Cover Mode: непрерывное удержание заголовка Gallery 3 секунды → системная аутентификация Android → отдельное подтверждение сброса. Успешный recovery возвращает DEFAULT launcher state и удаляет временный Gallery access rule/key, но сохраняет локальные зашифрованные данные Gallery.

## Lifecycle и переключение Cover Mode

При переходе из Gallery в другой Cover Mode временный hidden-access verifier/key удаляется, а фотографии, альбомы и Favorites сохраняются. При следующей активации Gallery секретное изображение и последовательность выбираются заново. Удаление текущего secret image инвалидирует только access rule; данные Gallery и сама активная маскировка остаются, поэтому сохраняется аварийный recovery.

## Границы автоматической проверки

Автотесты покрывают локальное хранилище, sanitization, access persistence, переходы Cover Mode, отсутствие широких media permissions, восстановление атомарного индекса, copy-on-write редактирование и очистку orphan-файлов. Поведение на физических устройствах, OEM-варианты Photo Picker, пиковое потребление памяти на очень больших изображениях и экстремальные значения font/display scaling остаются ручными проверками.
